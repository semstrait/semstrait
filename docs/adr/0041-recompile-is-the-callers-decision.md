# Recompile is the caller's decision; the manifest is content-addressed by its model fingerprint

> **Amended.** Later ADRs changed parts of this decision. Where they differ from the text below, the later ADR governs.
>
> - [ADR 0043](0043-authored-primitives-get-typed-carriers.md): documentation is carried in the manifest, so "documentary fields stay out of the manifest" no longer holds; prose moves the fingerprint whether or not the manifest carries it, so the churn is paid regardless and the artifact may as well hold the value.
> - [ADR 0046](0046-physical-source-is-flat-with-explicit-schema-provenance.md): `PhysicalSource` reserves no statistics carrier, refusing the "optionally statistics" 0041 invited; glob expansion happens at compile, and manifest determinism narrows again: a file appearing between two compiles changes the correct artifact while triggering no recompile, and the stale artifact keeps the same content-addressed key. File sources thereby land in exactly the position catalog drift occupies, detected out of band by a caller-scheduled check, except that no file-drift verb exists.
> - [ADR 0055](0055-manifest-provenance-is-caller-supplied-and-reverse-indexes-are-not-persisted.md): "No second timestamp field is minted" is superseded on carrier grounds: `updated_at` is minted beside `created_at`, reserved, and given a writer; the rest of that clause stands, including that the freed word "epoch" is not reused. "Manifest state is never modified at all" is corrected to *no load-bearing state is ever modified* (0055's *ADR 0041's "manifest state is never modified at all" is corrected, not repealed*); its operative content is untouched: the content-addressed key, the fingerprint's preimage, the refusal of a per-document pointer, and the placement of the gate outside the crate. Compile's input tuple gains a provenance instant, so its output is no longer a function of `(model, catalog, filesystem)` alone; manifest determinism is unaffected, since 0041 already narrowed it to exclude non-load-bearing provenance as a class, not as one field.

## Context and Problem Statement

Requirement 6a reads: "manifest state can be only modified by another compile trigger when the hash of a model is changed from the previous compilation pass". Who owns the recompile gate, what does the model fingerprint cover and which trait carries it, what do `manifest_epoch`, `created_at` and `catalog_fingerprint` become, and what blocks 6a under the default identity profile?

## Considered Options

- A caller-owned recompile over a store content-addressed by `model_hash`, the fingerprint being SHA-256 `[u8; 32]` over `serde_json` of the model with the root `id` nulled, and a real `created_at` with manifest determinism narrowed (chosen).
- **A mutable current-manifest pointer keyed by the root `id`.** It is new persisted state whose only clients are retention and audit, neither of which 6a asks for, and a caller holding a model never needs to know what the *previous* pass was — only whether *this* model is already compiled.
- **A hand-rolled structured walk** in the style of `fn schema_fingerprint` / `fn update_len_prefixed`, the only candidate insensitive to wire spelling. It must enumerate fields, so a *forgotten* field silently under-covers, converting a maintenance slip into a wrong answer.
- **Routing the preimage through the model's own `Persistable::to_bytes`.** That codec is YAML under a `semantic_model:` envelope, the model's *persistence* wire, whereas `model_hash` is a manifest field belonging to the manifest's JSON canonical-byte discipline; hashing through it would make a content digest sensitive to an envelope and to `serde_yaml`'s formatting choices.
- **MD5.** Its 16 bytes would change a ratified persisted shape, but the standalone objection is that the failure mode this digest guards is a *missed* recompile, so collision resistance is the property being bought and a broken digest cannot buy it.
- **A UUID-shaped digest.** "Hash the content into a UUID and use that" collapses on inspection to *drop `model_hash`, keep `model_id`*, since a UUIDv5 is a SHA-1 digest truncated to 128 bits with six bits overwritten by version and variant nibbles, and `model_id` is already `UUIDv5(model_hash)`. Refused because `model_id` is constrained to canonical UUID text, so it would spend roughly 122 bits where 256 are already ratified, implemented, and free.
- **Keeping the `created_at` stamp fake forever**, the alternative to narrowing manifest determinism — what `FIXED_CREATED_AT_SECS` was doing and admitted in its own comment.

## Decision Outcome

`compile()` stays an unconditional, pure function of `(model, catalog, filesystem)`: it gains no prior-manifest argument, no `compile_if_changed` sibling, and no comparison against anything persisted. Requirement 6a is satisfied structurally rather than by a guard, because the manifest store is already **content-addressed on `model_hash`**. Whoever holds the model decides whether to recompile; `semstrait-manifest` supplies the fingerprint that decision reads and nothing more.

**The gate has no home here, because the store already is one.** Four facts compose into it. `SemanticManifest::entity_id()` returns `model_id`; `model_id` is minted as UUIDv5 over `model_hash` and nothing else (`fn mint_model_id`); `FileSystemRepository::key_for` composes `base/{id}.{extension}` with, in its own words, "no second namespace axis"; and `Repository` already exposes `exists(&EntityId) -> Result<bool, _>`. So a caller computes the fingerprint with no I/O, asks `exists(mint_model_id(&fingerprint))`, and `load()`s on a hit. An unchanged model lands on the key it already occupies; a changed model lands on a new one. R8's last-writer-wins can therefore only ever fire for a byte-identical fingerprint, which means **manifest state is never modified at all** — the property the original recompile-gate ask wanted, obtained by construction rather than by a check someone must remember to run.

**The lineage the original ask literally wanted is refused, not overlooked.** "From the previous compilation pass" describes a per-document pointer, and the artifact deliberately cannot express one: the fingerprint's preimage nulls the model's root `id`, so the artifact carries no handle on the *document* it came from — only on the content (`model_id` identifies *this compilation*, the root `id` identifies *which document*). Content addressing therefore buys dedup and reuse but no history, and "what is the current manifest for document X" has no answer. Retention and garbage collection of superseded artifacts are out of scope, and stay unowned until something asks for them.

**ADR 0024's "caches nothing" must be read narrowly, because the `Repository` is a cache.** That ADR leaves "manifest reuse and drift re-validation to the caller's `Arc` pattern" and warns that an internal cache would change the freshness semantics callers build on. It remains binding on the *orchestrator*, which memoizes nothing. It says nothing about the persistence seam, and cannot: a `FileSystemRepository` over `InMemoryFileSystem` is precisely a cache, and whether the store is durable or in-memory is the adapter's choice at construction. So the layering is: this crate defines the artifact and its fingerprint, the seam stores it by content, and the caller — or a higher API — decides whether to consult the store at all. The ratified `38` surface is already shaped for exactly this and gains nothing: `compile_from_*`, `save_manifest`, `load_manifest`, `validate_manifest`, with no conditional compile among them.

**Catalog drift is not a trigger input, because it already has a ratified home.** The lifecycle contract has long-lived manifests re-validated out of band via `SemStrait::validate_manifest`, with a `Breaking` `DriftStatus` meaning re-compile, and the orchestrator contract walks the persisted `sources` calling `CatalogProvider::check_schema_drift` per source. Drift is therefore detected against per-source data by an async check the caller schedules, never by a model fingerprint that cannot see it. One collision is named here: two compiles of the *same* model against *different* catalog states address the same key, so a caller that gates on `exists` alone will not notice catalog movement. That is the caller's to sequence — drift re-validation before reuse — and it is the reason the drift check exists as a separate verb.

**The fingerprint preimage stays serde-total, and totality is the whole argument.** `model_hash` remains SHA-256 over `serde_json::to_vec` of the model with the root `id` nulled. The dangerous failure direction is two *different* models producing the *same* fingerprint — a recompile skipped and a stale manifest served — while the harmless direction is a spurious recompile. Serde over the whole type is total by construction: every field participates, and a newly added authoring field is covered the day it lands. This pins the encoding that the earlier contract never pinned.

**Nulling the root `id` buys stability across a change of document *identity*, not across a rename — and the ratified rationale for it is wrong.** The earlier contract justified the exclusion on the ground that "folding document identity into a content hash would flip `model_hash` on a rename that changed no semantics." That benefit does not exist: `SemanticModel.name` is a plain `String` with no skip attribute, so it is always in the preimage, and `model_hash_excludes_root_id_but_not_content` asserts in terms that renaming moves the hash. A rename flips the fingerprint whether or not the id is nulled. What the exclusion delivers is the property the dedup gate rests on: a model **re-authored under a different root `id`** — copied into a new document, or re-keyed — with otherwise identical content produces the same fingerprint, the same compilation identity, and therefore the same key, so the store addresses *meaning* rather than *documents*. The second reason is independent: a derived root id is `UUIDv5(ROOT_NAMESPACE, name)`, a pure function of a field already in the preimage, so including it would add no entropy in the derived case and pure noise in the authored one, while making the fingerprint depend on whether an author happened to write an id down — profile-dependence of the same class as the id-minting precondition below. The exclusion stands on these grounds; that contract's stated reason is frozen-text debt.

**MD5 and a UUID-shaped digest are both refused, on collision resistance.** The field stays `[u8; 32]`, and `model_hash` and `model_id` have two readers: a comparison reads the digest, a key reads the id, and neither has to re-derive the other.

**The accepted cost: a wire re-cut moves the fingerprint.** Because the preimage carries JSON key order and wire-key spellings, re-cutting an authoring type changes `model_hash` and therefore `model_id` with the model's meaning unchanged — observed directly when the relationship join basis was renamed to `on:` and an absent `cardinality` began skipping. Composed with content addressing, a pure serde refactor orphans every stored artifact at a new key. This is accepted because a wire re-cut is a release event that coincides with a version move anyway, and because the consequence is a recompile that was not strictly needed rather than one that was needed and skipped. The prose-only edit case is accepted on the same ground and for the same reason it was already parked: documentary fields stay out of the manifest, so editing prose churns the fingerprint while producing a materially identical artifact.

**The fingerprint is carried by a codec-free trait beside `Persistable`, not by a free function and not by a shared codec.** `common` declares a fingerprint trait that names a **preimage**, never a format; each state crate implements it for its own type, and the crate dependency DAG enforces the direction exactly as it does for `Persistable`. This is required by the ruling of 2026-07: **opaque per-DTO codec, no shared codec enum in `common`** — a ruling whose own rationale names our trade-off and rejects it, since a shared codec exists precisely so that "`manifest_epoch`-style fingerprints hash a known canonical form". The trait cannot be `Persistable` itself: that impl's `integrity_check` **refuses an id-less model**, which is the very projection the preimage performs, so the id-nulling step lives inside the model's fingerprint impl where the two requirements cannot collide. The extension point is the preimage and digest only — **comparison is not part of it**, being equality on `[u8; 32]` performed by whoever owns the gate, which this ADR places outside the crate. The trait is designed to be implementable at *component* granularity, so a later partial-parse or partial-update path can rehash only what changed rather than the whole document.

### `manifest_epoch` becomes `manifest_version`

**The name was load-bearing wrong, not merely infelicitous.** The field versions the persisted structure: the earlier contract has it bump "when canonical encoding of the manifest changes", and ADR 0040 rules that it "fences manifest-shape changes rather than model-hash changes", that 1 → 2 is "the single bump", and that one bump "also covers churn it did not cause". "Epoch" invites the opposite reading — a generation or time marker that moves on its own — and two ratified clauses took it: the earlier contract has provider-internal drift "propagate into `manifest_epoch` via canonical encoding", and the binding-expression contract has per-source fingerprints feed it "implicitly", with schema drift flipping "the canonical bytes and bump[ing] the manifest hash". There is no manifest-hash field at all, and an automatically-moving version would renumber `bit_position` on every catalog change against ADR 0036. The only cross-crate consumer already reads it the ratified way and says so: `SegmentKey.manifest_epoch` is documented as the "Manifest **version channel**… the only version dimension a fragment is keyed on". Renaming to `manifest_version` retires the misreading instead of leaving it to be re-derived.

**The rename is free now and expensive later.** `2` has never shipped, and 0040's rule is that one bump absorbs every later shape change until release — so the rename rides the existing move and costs no additional version. After release it would cost a migration. The renaming supersedes the earlier contract's field name, and its provider-drift clause plus the binding-expression contract's per-source-fingerprint clause are superseded outright: nothing feeds the version implicitly, and no fingerprint bumps it.

**`SegmentKey` keys on `manifest_version`, and never on a timestamp.** This is the operative consequence for `semstrait-ir`. A version-keyed fragment survives recompiles of an unchanged structure, which is what a plan-fragment cache is for; a timestamp-keyed one is invalidated by every compile.

**`created_at` becomes a real stamp, which narrows manifest determinism.** The manifest carries exactly one time, on its metadata block, and it stops being a fixed constant. No second timestamp field is minted and the freed word "epoch" is not reused. This requires narrowing **manifest determinism** — "SemanticManifest determinism for identical `(model, catalog snapshot)` inputs" — to exclude non-load-bearing provenance, because a wall clock otherwise makes identical inputs produce different artifacts. The narrowing is the decision. Determinism is preserved where it is load-bearing: the fingerprint never reads the stamp, so content addressing, dedup and id minting are untouched, and byte-comparison of two artifacts must exclude provenance — which is also what the committed-snapshot tests must now assert.

### `catalog_fingerprint` is retired

**It gets no aggregation rule, because it does not survive.** The top-level `Option<[u8; 32]>` is removed rather than given the fetched-content aggregation the earlier contract specified. It has never had a reader — every site in the tree is the declaration, the constructor threading it through, a test asserting `None`, or a comment — and the two jobs it was imagined for are now placed elsewhere: recompile triggering is the caller's and reads the model fingerprint, drift detection is `validate_manifest`'s and reads per-source data. A single opaque digest over the whole catalog can serve neither, since it cannot say *what* moved. This supersedes the earlier contract's catalog-hash clause, and makes the binding-expression contract's clause ("identity-only hashing would miss provider-internal drift") moot rather than wrong — nothing hashes the catalog as a whole in either style.

**What replaces it is base catalog configuration metadata for identification and traceability, plus per-source format descriptors.** The manifest records enough of the catalog configuration to say which catalog an artifact was resolved against; it does not digest it. The load-bearing content moves onto `PhysicalSource`, which carries the descriptors its underlying data format actually has — for Iceberg, `schema_id`, the schema itself, a partition definition, and optionally statistics — because those are what a correct `PlanNode` is constructed from, and a digest of them is not. Their exact shape is not ruled here: it is a `PhysicalSource` carrier question and belongs with the creation-forks and engine-specialization decision.

### The precondition this ADR cannot satisfy

**Requirement 6a is unreachable until id minting is deterministic from content.** Under the default `IdentityProfile::ConvenienceGenerateMissing`, an entity that omits its `id` is minted `Uuid::now_v7()` — "Time- and RNG-based, so values vary across runs", in the generator's own words. Every entity `id` serializes when present and every one is `Some` after parse, so each fresh mint sits inside the fingerprint's preimage: **parsing the same document twice yields two fingerprints, two compilation identities, and two artifacts.** No digest choice repairs this. The crate's belief that "manifest determinism holds because output is name-ordered, never id-ordered" is true but insufficient — it defends collection *ordering* while the fingerprint reads the id *values* — and manifest determinism itself is scoped to identical `(model, catalog snapshot)` inputs, meaning identical model *values*, so the ratified determinism claim deliberately stops short of parse. The existing tests pass around the gap rather than through it: determinism is asserted by compiling one in-memory model twice, and the snapshot fixture hand-builds fixed ids.

**What this ADR decides, and what it hands on.** It decides that the precondition is real and **blocking**: entity id derivation must become a function of content, and until it does, the recompile behaviour this ADR defines cannot be exercised under the default profile. It does **not** decide the derivation. That is a `semstrait-model` parse-stage question — which namespace, which seed, and whether `IdentityProfile` survives at all — and it is a decision, not a code task.

The likely shape, already templated in the same module: `derive_root_id` mints the *root* deterministically as UUIDv5 over a frozen namespace and the model's name, documented as yielding the same id "across parses, machines, and time — unlike `generate_entity_id`", so extending name-based v5 derivation from the root to its children is the obvious candidate. The one thing known to be wrong with the naive version is the seed: a bare name will not do, because names are only unique within a parent — the manifest's own minter already seeds on `(owning DataKind, name, role)` for exactly this reason — so it needs a scoped path. Two costs are known in advance and belong to whoever rules it: the change re-derives every id-less model's ids and so orphans their stored artifacts, the same one-time break the root namespace is marked "**Frozen for all time**" to avoid, which forces it into the same pre-release window as `manifest_version`; and it edits a crate this decision does not own.

### Amends

- **0012:** `manifest_epoch` is renamed `manifest_version`.
- **0016:** `catalog_fingerprint` is retired, so nothing hashes the catalog as a whole, by identity or by fetched content; drift detection reads per-source data.
- **0024:** "caches nothing" must be read narrowly, because the `Repository` is a cache; it remains binding on the *orchestrator*, which memoizes nothing.
- **0040:** `manifest_epoch` is renamed `manifest_version`, and the rename rides the existing move and costs no additional version.
